# 用户钱包 MVP 开发 TODO

本文档用于跟踪“用户注册 / 预付费钱包 / 自助 Key / 按量扣费”的开发计划。

详细设计见 `docs/user-wallet-mvp.md`。

## 0. 当前约束

- 只做预付费。
- 只做钱包余额。
- 只做按实际用量扣费。
- 价格表继续复用现有 `price`。
- 实际消费金额继续复用 `CalculateAmountDetail(...).UsedAmount`。
- 支付成功只做“充值余额 + 记一条充值流水”。
- 不做退款、撤单、套餐有效期、赠金、优惠券、后付费、月结、发票。
- 不新增模型与 `group` 的关联管理功能，直接复用现有配置。
- 所有启用中的 `group` 对用户透明可选，不做用户级 group 授权。

## 1. 开发原则

- 后端先于前端。
- 数据模型先于接口。
- 钱包事务先于模型扣费接入。
- 用户自助 Key 必须先绑定 `owner_user_id`，再接入钱包扣费。
- 现有管理员 Key、内部 Token、未绑定用户的旧 Token 默认不走用户钱包扣费。
- 管理端可以管理用户，但用户删除默认采用禁用或软删除，不做物理删除。
- 管理端不需要查看用户自助创建的 Key；现有后台 Token 列表应默认过滤 `owner_user_id` 不为空的用户 Key。
- 钱包预占、结算、释放必须同步执行；请求日志和消费日志可以继续使用现有异步流程。
